# TicketInsight 需求说明

## 业务目标

为客服主管、售后运营与产品运营提供“从工单中找证据、从数据中做统计、给出可复核建议”的分析工作台。系统不是客户聊天机器人，所有结论都必须标注数据、工单或 SOP/FAQ 依据。

## V1 核心能力

1. 管理脱敏模拟的客户、工单、SLA、产品模块、工单事件和服务知识。
2. 将工单、FAQ、SOP、已知问题、类别定义写入统一向量索引。
3. 从自然语言问题提取时间、类别、模块、优先级和 SLA 等条件。
4. 由 Agent 规划一条只读 SQL；由代码进行 AST、白名单、超时和行数校验后执行。
5. 用 LangGraph 编排检索、规划、查询、归因、复核五类节点。
6. 保存运行轨迹、检索证据、SQL 审计、结论、耗时与匿名反馈。
7. 用固定题集验证检索、SQL 正确性、危险 SQL 拦截和结论依据。

## 关键假设

- 数据规模为演示级别，使用本地 MySQL 与 Qdrant 即可。
- 工单正文和服务知识均为不可信输入，必须按文本证据处理，不能当作指令。
- LLM 只处理理解、规划、归因与表达；不直接访问数据库，也不能进行外部写入。
- 初期不需要前端，以 Swagger 和演示脚本完成演示。
- 只采用一个本地中文 Embedding 模型；不训练或微调模型。

## 验收问题示例

- 为什么本周支付类投诉比上周多？
- 列出已经超过 SLA 的高优先级工单，按模块统计。
- 登录模块最近积压最多的问题是什么？
- 哪些匿名客户在一周内重复反馈同类问题？
- 针对登录失败，现有 SOP 推荐如何处理？

## 安全红线

- 禁止 DDL、DML、多语句、跨库、存储过程和高风险 SQL 函数。
- 禁止自动回复客户、自动关单、改优先级、派单或调用外部服务。
- 禁止将凭据和个人可识别信息写入仓库或日志。
- 条件不清晰时必须先澄清，不能编造统计口径。
